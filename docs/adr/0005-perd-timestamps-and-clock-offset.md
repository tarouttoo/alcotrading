# Метки времени PERD и поправка часов биржи в Parquet-схеме

Q30 фиксировал две метки на запись: биржевое время и локальное время
получения. Вычитка книги (тикеты #7 и #12) показала, что этого мало:
конвертация схемы после старта записи болезненна (кейс alko — float-timestamp
и сортировка по времени доставки перевернули полгода тестов), часы бирж
гуляют каждая по-своему (binance −0,2 мс, bybit −2 мс, okx ±2,5 мс), и без
записанной поправки кросс-бирженное сравнение биржевых меток невозможно.
Решение: каждая запись несёт четыре nullable-колонки int64 микросекунд —
`tsEvent` (событие у матчинга), `tsPush` (пуш биржи; null, где биржа не
различает — честный пропуск вместо дублирования), `tsReceived` (локальный
приём WS-фрейма, до парсинга), `tsDelivered` (принятие в очередь
потребителя: буфер писателя Parquet в фазе 1, вход в ядро стратегии в
live) — и колонку `exchangeClockOffsetUs` (биржевые − локальные часы;
замер server time REST раз в 60 с, колонка несёт последнее измеренное
значение).

Маппинг по биржам: Binance сделки `tsEvent=T`/`tsPush=E`, книга
`tsEvent=E`/`tsPush=null`; Bybit книга `tsEvent=cts`/`tsPush=ts`, сделки
`tsEvent=T`/`tsPush=null`; OKX `tsEvent=ts`/`tsPush=null` во всех каналах.

## Considered options

- **Оставить две метки (Q30 как есть)** — отвергнуто: добавить колонки
  позже — разнородные файлы в одном датасете; `tsReceived` и `tsDelivered`
  у нас различимы уже в фазе 1 (очередь писателя).
- **Добавить только `tsDelivered`** — отвергнуто: `tsPush` у Bybit (`ts`)
  и сделок Binance (`E`) биржа уже отдаёт, резервировать её бесплатно.
- **Полный PERD без поправки часов** — отвергнуто: главная ценность четырёх
  меток — кросс-бирженный анализ; без offset-колонки биржевые `ts`
  несравнимы, а восстановить поправку пост-фактум нельзя.

## Consequences

- ~24 байта на запись на nullable-колонках; Q39 (int64 мкс, никаких float)
  становится ещё критичнее: сортировка по времени доставки — прямой
  потребитель этих колонок.
- Периодический REST-замер server time (60 с) ложится в тот же
  планировщик, что и REST-сверки Q60, — учесть лимиты.
- Точка простановки `tsDelivered` в фазе 2 смещается с писателя на вход в
  ядро стратегии; семантика колонки («доставлено потребителю») не меняется.
